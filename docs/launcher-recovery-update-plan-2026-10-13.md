# 게임 업데이트 대응 복구 업데이트 계획

게임 업데이트로 BetterAstralParty의 호환성 검사가 실패해도, 사용자가 호환되는 새 모드를 받을 수 있도록 게임 내 업데이트와 게임 실행 전 런처 업데이트 경로를 함께 제공한다. 긴 경로 보완을 포함한 로컬 개발 대상은 `1.3.0-rc.1.local.2`이며, 실제 설치와 GitHub 게시는 별도 요청으로 진행한다.

## 적용 범위

- 게임이 정상 실행되는 범위에서는 일반 모드 기능의 호환성 오류와 업데이트 확인·다운로드를 분리한다. 게임 UI나 로더 자체가 시작되지 않는 상황까지 게임 내 기능만으로 보장하지 않는다.
- 게임 실행 전 호환성 검사에 실패하면 기존 BetterAstralParty 런처에서 업데이트 전용 화면을 제공한다. 게임 호환성 차단을 해제하거나 검증되지 않은 모드로 게임을 시작하지 않는다.
- 기존 런처·공통 릴리즈 조회·다운로드·서명 검증·업데이트 도우미를 우선 재사용한다. 새 실행 파일이나 의존성을 늘리지 않고 현재 8개 업데이트 소유 파일과 프로토콜 3 계약 안에서 전달하는 것을 목표로 한다.
- 적용은 새 패키지의 검증된 게임 호환성 기준으로 판단한다. 저장소·채널·버전·서명·해시·설치 소유 기록·잠금·게임과 런처 종료 확인·백업·복구 보호를 유지한다. 다른 모드와 공용 로더 설정을 변경하지 않는다.

## 오탐지 위험과 실행 방식

- 업데이트 목적과 진행 상태를 사용자가 확인할 수 있는 정상적인 관리 코드 경로를 사용한다. 불필요한 셸 실행·임시 실행 파일·난독화·패커·자기 삭제 동작을 추가하지 않는다.
- 백신 설정 변경, 자동 제외 등록, 상주 서비스와 예약 작업은 추가하지 않는다. 창을 닫은 뒤 독립적으로 무기한 재시도하는 작업을 만들지 않는다.
- 현재 업데이트 서명 검증을 유지한다. 이는 Windows Authenticode 서명과 별개이며, 재사용이나 코드 개선만으로 백신 탐지 0을 보장하지 않는다. 새 산출물은 기능·안전성 검증과 실제 백신 확인을 구분해 기록한다.

## 기존 사용자에게 전달

1.2.1 이상 사용자는 기존 자동 업데이트의 런처 교체 경로로 새 기능을 받을 수 있도록 한다. 게임 업데이트 전에 새 기능을 받은 사용자는 이후 런처의 복구 업데이트 경로를 사용할 수 있다. 새 기능을 받지 못한 구형 런처가 이미 게임 실행을 차단하는 경우에는 새 패키지 수동 설치가 필요할 수 있다.

자동 업데이트는 설치된 파일을 갱신하며, 사용자가 이전에 다운로드한 패키지의 Install.cmd·Uninstall.cmd나 ZIP을 덮어쓰지 않는다. 1.2.0 이하의 지원 종료 정책은 유지한다. 기존 채널 선택과 다운로드·종료 후 적용 설정을 존중하고, 비공개 채널의 인증을 임의로 저장하거나 공개 채널로 조용히 대체하지 않는다.

## 대응 패치가 없거나 확인이 실패한 경우

- 조회에 성공했지만 적용 가능한 호환 업데이트가 없으면 그 상태를 명시하고 설치된 파일·설정·백업을 변경하지 않는다.
- 새 버전이 존재해도 현재 게임과 호환되는지 검증되기 전에는 적용하지 않는다. 최신 버전이라는 이유만으로 강제 설치하거나 같은 구버전을 반복 적용하지 않는다.
- 네트워크 오류·인증 만료·접근 거부·요청 제한·첨부 누락·잘못된 서명·해시 불일치는 각각 확인 실패나 검증 실패로 표시한다. 확인하지 못한 상태를 패치 없음으로 표시하지 않는다.
- 게임·런처·도우미 사용 중이면 검증된 종료 대기와 재확인·취소를 제공한다. 권한 부족·소유 기록 손상·복구 대기는 진단과 안전한 복구 또는 수동 설치 안내로 연결한다. 강제 종료, 임의 덮어쓰기, 무한 재시도는 하지 않는다.
- 화면에는 재확인, 순정 Steam 클라이언트로 실행, 진단 ZIP 만들기, 닫기를 제공한다. 순정 Steam 클라이언트로 실행하면 BetterAstralParty만 미적용하며 다른 모드까지 비활성화하지 않는다. 재확인은 화면이 열린 동안에만 기존 제한·대기 정책을 적용한다.

## 구현 시 검증 항목

- 1.2.1에서 새 기능을 받는 자동·수동 업데이트와 지원 버전 건너뛰기, 기존 런처·도우미 계약, 안정판·비공개 채널 및 전환 확인.
- 게임 코드·카탈로그 변경, 실행 중 변화, 새 패치 없음, 새 패치도 비호환, 조회 실패와 확인된 패치 없음의 구분.
- 다운로드 취소·시간 초과·요청 제한·디스크 부족·읽기 전용·파일 잠금·백신에 의한 파일 누락·손상 패키지·잘못된 서명.
- 게임과 런처 종료 전 적용 금지, 중복 실행·중단·재시도·복구, 설정·다른 모드·공용 로더·백업 보존.
- 새 런처 단계와 판단 이유를 기존 진단 기록에 남기고 진단 ZIP 수집·누락 보고·개인정보 가림까지 검증. 한국어·영어 표시와 실제 화면 동작을 별도로 확인.

## 구현 규약

- 검증된 Unity 프레임 드라이버를 카탈로그 검사보다 먼저 등록한다. 일반 UI가 차단된 프레임에도 업데이트 backend와 기존 소유 카메라의 원상복구 재시도는 처리하지만, 새 게임 UI·매칭·PvP 조회에는 진입하지 않는다. 복구 예외는 프레임 처리를 중단하지 않는다. 드라이버 등록이나 로더 시작 자체가 실패하는 경우는 런처 경로가 필요하다.
- 복구 화면은 기존 런처의 WinForms와 운영체제 기본 글꼴을 사용한다. .NET Framework 4.8 대상 메타데이터로 운영체제의 TLS 기본값을 사용하며, 새 배포 EXE·DLL이나 시스템 설정 변경은 추가하지 않는다.
- 릴리즈 조회와 다운로드 검증에서는 설치 파일을 변경하지 않는다. 사용자가 적용 버튼을 누른 뒤에만, 새 패키지의 호환성과 서명된 helper를 다시 확인하여 기존 도우미로 인계한다. 저장된 자동 다운로드 OFF를 유지하며 명시적인 수동 적용은 종료 후 적용 설정을 덮어쓰지 않는다.
- 기존 게임 PID를 사용하는 프로토콜 3 티켓은 유지한다. 런처 전용 티켓은 게임 신원을 정확히 `0:0:0`으로 비워두되, 현재 루트의 실제 런처 PID·생성 시각·세션을 검증한다. 이 티켓을 보내기 전 서명된 helper 버전 `1.3.0-0` 이상을 요구한다. 필요한 helper 교체는 기존 승인된 교체 흐름을 사용하며, 게임과 런처가 종료됐는지 확인한 뒤에만 모드 파일을 적용한다.
- 자동 재확인은 복구 창이 열려 있을 때만 제한된 메타데이터를 조회한다. 동일한 비호환 ZIP을 반복 다운로드하지 않으며 서버 대기 안내를 따른다. 비공개 인증은 기존 사용자 인증 저장소를 읽기만 하고, 인증이 없으면 수동 설치를 안내한다.
- `NoCompatibleUpdate`와 `CompatibilityRejected`를 조회 실패와 구분해 기록한다. 소스 로그와 진단 ZIP에서 제한된 로컬 개발 버전도 유지하되, 인증·URL·개인 경로·임의 문자열은 포함하지 않는다.
- 설치·제거·업데이트·백업·진단 수집은 공통 경로 검증 후 실제 파일 접근에만 Windows 확장 경로를 사용한다. 설치 기록과 로그의 경로 표기는 유지하며, 경로 이탈·링크·예약 장치명 검증을 완화하지 않는다. PowerShell 5.1 진단 도구는 긴 소스 파일명을 컴파일러에 넘기지 않고 기존 두 소스의 내용을 메모리에서 컴파일한다. Windows가 CMD 파일 자체를 열지 못하는 경로에서는 패키지를 더 짧은 경로에 풀어 실행해야 한다.

## 현재 코드 근거

- `updater/UpdateTrust.cs`의 정확한 업데이트 소유 목록에 런처·호환성 기준·검사 스크립트가 포함된다.
- `updater/UpdateCompatibility.cs`와 `updater/UpdateTransaction.cs`는 들어오는 새 패키지의 호환성 기준으로 적용 여부를 검사한다.
- `updater/UpdateHelperService.cs`는 게임과 런처 종료를 기다린 뒤 검증된 업데이트를 적용한다.
- `tools/SteamLauncher.cs`는 호환성 검사 실패 시 게임 시작 전에 중단하고, `tools/LauncherRecoveryForm.cs`와 `tools/LauncherRecoveryClient.cs`로 업데이트 확인·다운로드·적용 인계를 제공한다.
