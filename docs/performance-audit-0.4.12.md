# 0.4.12 성능 점검 — 2026-09-20

## 범위와 판단

모든 기능의 진입점 `ModUi.Tick`부터 전투/카드 추천, 이름 치환, 카드 핑, 전투 공개 상태, 설정창, 표시/모션, 공통 런타임 연결, 진단/실행기를 점검했다. 최신 0.4.11 BepInEx 로그에서 반복 예외 루프는 발견하지 못했다. 기존 로그에는 프레임별 소요 시간이 없으므로 간헐적인 렉을 특정 기능이나 공식 클라이언트 탓으로 확정하지 않는다.

| 경로 | 확인한 비용 | 변경 |
|---|---|---|
| 캐릭터 본명 | 활성 UI 최대 4,096개를 한 프레임에 순회 | 중단/재개 가능한 깊이 우선 탐색, 프레임당 최대 64 작업 및 약 1ms 예산, 완료 후 0.2초 휴식 |
| 전투 계산 | 내부 조합마다 쓰지 않는 한국어 설명 문자열 생성 | 수치 계산 경로에서는 설명 생략, 화면에 표시하는 결과/설명 유지 |
| 카드 계산 | 위 문자열 + 매 조합마다 bool 배열 생성 | 문자열/배열 제거, 기존 범위 제한과 카드 결과 캐시 유지 |
| 같은 전투 입력 | 0.2초마다 같은 범위 재계산 | 최근 입력 한 개의 순수 계산 결과 재사용, 게임의 선택 가능 여부는 계속 갱신 |
| 전투 공개 상태 | 변하지 않은 효과도 원본 렌더러 재호출 | ID/종류/진행/남은 턴 변경 시만 렌더링, 페이지·대상 변경 시 갱신 |
| HP 추적 | 매 프레임 UI 필드/디스플레이/카메라 래퍼 재조회 | 참조/크기 재사용, 화면 크기 조회 공유, 실제 HP 위치 투영은 매 프레임 유지 |
| 공통 연결 | 클래스·필드 상속 탐색, 인자가 문자열이 아닌 호출에도 List 생성 | 성공한 메타데이터만 캐시, 문자열 인자 있을 때만 보존 목록 생성 |
| 호버 | 기능마다 같은 touchTarget 부모 경로 순회 | 프레임 단위 공유, 버프 번역/설명 갱신은 0.2초 단위 |
| 카드 핑 | 클릭하지 않을 때도 핑 텍스트 조회 | 클릭 down/up 때만 조회, 발견한 창 재사용 |
| 모션/설정창 | 등장 모션 완료 후에도 동일 속성을 매 프레임 쓰기 | 값이 같으면 쓰기 생략, 기존 등장/퇴장/호버 시간 유지 |
| 로그 | OFF에서 파일 쓰기 없음, ON은 상태 변화 중심 | 기본 OFF 유지, ON에서만 10초 숫자 집계 추가 |
| 실행기 | 실행별 Doorstop 옵션, Steam 기본 OFF | 변경 없음, 설치본/설정 정적 검사 |

이름 치환은 거대한 창에서 모든 이름을 바꾸기까지 여러 프레임 걸릴 수 있다. 시간 예산은 개별 네이티브 호출 중단을 강제하지 않으므로 한 번의 호출이나 초기 번역표 로딩이 1ms를 초과할 수 있다. 원본 렌더러 이벤트 후킹이나 네이티브 스레드 변경은 추가하지 않았다.

동일 컴퓨터의 .NET 8 Release 순수 계산기. 워밍업 15회, 30회 반복의 샘플 7개 중앙값. 관리 할당은 현재 스레드의 `GC.GetAllocatedBytesForCurrentThread`. UI/IL2CPP/GPU는 이 측정에 포함되지 않으며 로더의 실제 .NET 6 성능과 다를 수 있다.

## 실제 플레이 측정 방법과 한계

기존 설정의 `충돌 진단 로그`를 ON으로 하고, 메인메뉴 → PvE 카드 선택 → 방어/회피 → 관전 → 필드 → 메인메뉴 순으로 플레이한다. 특히 효과 추가/소멸, 중첩/남은 턴, HP 이동, 효과 6개 초과 시 휠, 호버, 이름 토글 복원, 핑 클릭/외부 클릭/ESC, 설정창 재열기를 확인한다.

`8vJXnINT/BepInEx/BetterAstralParty-Diagnostics/current.log`의 `performance` 줄:

- `ui_avg_ms`, `ui_max_ms`: 모드 UI 작업 평균·최대 시간. 로그 요약 쓰기는 포함하지 않는다.
- `gameui_max_ms`: 이름 치환·추천·홈 UI 등 GameUi 작업 최대 시간.
- `popup_max_ms`, `status_max_ms`: 핑 팝업/공개 상태 기능 최대 시간.
- `managed_bytes_per_frame`: 측정 구간의 .NET 관리 할당. IL2CPP/네이티브/GPU 할당이나 잔존 메모리량이 아니다.
- `game_frame_max_ms`, `game_frames_ge50ms`: 관측한 게임 프레임 간격의 최댓값과 50ms 이상 횟수. 모드만의 지연이나 정확한 같은 프레임의 원인으로 해석하면 안 된다.

집계는 약 10초마다 한 줄이며 기존 1 MiB/2개 파일 제한을 따른다. 진단 OFF이면 타이머/할당 측정과 성능 로그를 수행하지 않는다. ON의 계측·파일 쓰기에도 작은 비용은 있다. 이 빌드는 실제 게임을 실행한 화면·프로파일 검증까지 완료한 것이 아니며, 간헐적 렉 해소나 네이티브 충돌 해결을 보장하지 않는다. 여전히 렉이 있으면 위 로그와 동일 조건 바닐라 플레이를 함께 비교한다.
