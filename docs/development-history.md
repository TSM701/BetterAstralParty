# Development History — BetterAstralParty

Archived from README.md on 2026-09-24. Original notes are preserved in Korean, including superseded implementations and historical verification limits; they are not a current feature specification. Start with the [project README](../README.md). Paths in these notes are relative to the project root unless stated otherwise.

Astral Party 국제판의 PvE 편의성을 개선하는 한국어 우선 모드입니다.

## 원칙

- PvE에서 화면에 공개된 정보만 사용합니다.
- PvP에서는 추천 기능을 활성화하지 않습니다.
- 자동 입력, RNG 예측, 네트워크 변경, 게임 수치 변경을 하지 않습니다.
- 게임 번들과 `data.unity3d`를 수정하지 않아 비공식 한국어 패치와 공존합니다.

## 현재 구현

### 0.4.60 전투 버프 타입 검사 오탐 수정

- `Runtime argument mismatch: System.Object`로 전투 공개 상태가 차단되던 원인을 수정했습니다. 문자열은 네이티브 `System.String` 참조로 전달되므로, 문자열을 수용하는 `System.Object`/인터페이스 필드·인자도 실제 네이티브 타입의 대입 가능성 검사로 허용합니다. 값 타입·무관한 참조 타입·by-ref 인자는 계속 차단합니다.
- 버프의 `GObject.data`에 설명 문자열을 저장하는 원본 경로와 호환성 안전장치를 유지합니다. 0.4.59의 조기 생성·HP 기준 배치도 유지합니다. 실행 중 이미 차단된 상태는 새 버전으로 게임을 재시작해야 해제됩니다.
- 생산 코드의 인자 검사 메서드를 추출한 독립 검사에서 정상 문자열→Object/인터페이스 및 잘못된 타입 거부를 확인합니다. 이 검사는 메타데이터 대역을 사용하며 실제 게임 렌더링 검증을 대신하지 않습니다.

### 0.4.59 관전 전투 버프 사전 생성

- 공개 상태 행을 카드 사용 단계(3)가 아닌 전투 연출 단계(2)부터 준비합니다. 최초 생성/데이터 연결은 0.2초 주기를 기다리지 않고 매 프레임 확인하며, 준비 후 공개 버프 갱신 주기는 유지합니다.
- 양쪽 캐릭터 UI가 모두 보일 때까지 생성하지 않던 조건을 제거했습니다. 실제 표시는 각 HP의 가시성·전투 카메라·화면 좌표를 계속 따르고, 원본 도입 영상보다 아래에 배치합니다. 버프 공개 필터·PvE 제한·OFF/전투 종료 정리와 반격의 0.75초 지연은 유지합니다.
- 진단 로그의 `battle status create begin; step=…`으로 생성 단계를 확인할 수 있습니다. 빌드·단계/수명 정적 회귀 검사 대상이며 실제 관전 화면 확인은 별도입니다.

### 0.4.58 한자 필드 닉네임

- 한자가 포함된 플레이어의 **필드 닉네임**에만 M PLUS Rounded 1c Bold를 적용합니다. 닉네임은 원본 `GetNick(false)` 결과를 그대로 쓰며, 기본 한글/영문 닉네임·HP·버프·메뉴 폰트는 변경하지 않습니다. 기존 하늘색 내부와 검은 테두리를 유지합니다.
- 지정 TTF를 모드와 함께 배포해 게임 프로세스 안에서만 로딩합니다. Windows 폰트 설치나 게임 원본 폰트·전역 fallback 변경은 없습니다. 폰트 로딩에 실패해도 전체 필드 인디케이터를 끄지 않고 기본 이름표를 유지하며 로그에 기록합니다.
- 폰트 원본·저작권·OFL 1.1은 `assets/fonts/`에 보관합니다. 첨부 닉네임 `折鶴`의 글리프 포함 및 한자 판별을 자동 검사합니다. 폰트 자체에 없는 희귀 한자/문자의 표시까지 보장하지는 않습니다. 실제 게임 렌더링 확인은 별도입니다.

### 0.4.57 상대방 칩 핑 상세창

- 로컬에서 칩 선택창을 열지 않았어도 원본 `Relic` 패키지를 비동기로 준비하고 UI 클래스를 등록한 뒤 상세창을 생성합니다. 칩 선택창 자체를 열거나 선택/전송 동작을 실행하지 않습니다.
- 로딩 중 클릭한 칩과 위치를 유지합니다. 다른 핑으로 교체하거나 같은 핑/바깥/ESC를 누르면 취소하고, 설정 OFF·방 변경·설정창 열기·포커스 상실 시에도 취소합니다. 취소 후 로딩이 끝나도 상세창을 다시 띄우지 않습니다.
- 클릭 ID와 로딩 시작/완료를 로그에 남깁니다. 정상 로딩 대기는 호환성 오류로 처리하지 않으며 실제 로딩/리소스 오류는 기존 기능 격리를 유지합니다. 클릭 방식은 유지하며 호버로 열지 않습니다.
- 빌드·계산 자체 검사와 원본 로딩/바인딩 및 클릭 수명 정적 회귀 검사 대상입니다. 상대방 핑의 실제 게임 화면 확인은 별도입니다.

### 0.4.56 업데이트 호환성 보호

- 모드 실행기는 BepInEx를 켜기 전에 배포된 `BetterAstralParty.compatibility.json`과 SHA-256을 비교합니다. 실행 파일, GameAssembly, UnityPlayer, IL2CPP 메타데이터, 로더/네이티브 DLL, 기본 리소스, 로컬·다운로드 카탈로그가 대상입니다. 변경·누락·검사 실패 시 게임을 실행하지 않고 바닐라 실행기를 안내합니다. 로그는 게임 폴더의 `BetterAstralParty-Compatibility.log`입니다. 검사 완료 표식 없는 직접 모드 실행도 플러그인 초기화 단계에서 거부합니다. 이 표식은 실수 방지용이며 보안 인증 수단은 아닙니다.
- 실행 중에도 다운로드 카탈로그를 10초 간격으로 확인합니다. 변경 시 공통 모드 UI와 이에 의존하는 추천·인디케이터를 중단합니다. 로딩 중 아직 없는 화면은 기다리고, 기능의 타입 검사는 런타임/메인메뉴 준비 후 수행합니다. 네이티브 호출 인자, 필드 쓰기, 값 읽기의 타입·크기를 접근 전에 검사합니다. 임의의 다른 함수나 오버로드로 연결하지 않습니다.
- 공지 패치와 UI 드라이버를 분리하고 정확한 인자·반환형·static 여부를 검사합니다. 패치 실패 시 해당 그룹의 모드 패치만 해제합니다. 기능 실행 오류는 해당 세션에서 차단하고 모드 객체 정리·원본 이름/오디오 복원을 시도합니다. 정리 실패도 기록하며 매 프레임 실패 동작을 반복하지 않습니다. 사용자 설정값은 유지하고 정상인 설정창에는 `사용 불가` 및 호버 사유를 표시합니다. 공통 UI 자체가 실패하면 설정창 대신 로그를 확인해야 합니다.
- 설치기는 게임 실행 중 교체를 거부하고 기존 모드 DLL·설정·실행기·검사 기준을 `artifacts/install-backups/`에 보관합니다. Steam 기본 바닐라 실행과 원본 게임 리소스를 유지합니다.

**기준 갱신:** `tools/new-compatibility-baseline.ps1`은 유지보수용 스냅샷 도구입니다. 빌드·설치·실행에서 자동 호출하지 않고, 기존 기준 파일 덮어쓰기도 거부합니다. 새 게임/한글 패치 조합을 분석하고 계산 테스트 및 메인메뉴/비밀번호 봇방 확인을 마친 뒤 별도 기준 파일을 배포해야 합니다. 파일 해시가 달라졌다는 이유만으로 비호환이라고 확정하지는 않지만, 변경 의미를 확인할 때까지 실행을 보류합니다. 번역 전용이라고 확정할 수 없는 `data.unity3d` 변경도 보수적으로 차단합니다. 한글 패치가 없는 설치본 역시 별도로 검증한 기준이 필요합니다.

**검증 범위:** 현재 설치 조합의 사전 검사, 격리된 파일에서 코드/엔진/리소스 변경·누락·손상/신규 카탈로그 차단, 기능 격리·정리 실패·설정 보존 및 기존 전투/필드/폰트 회귀 검사 통과. 0.4.56의 실제 게임 화면·전체 네이티브 호출 검증은 사용자가 진행합니다. 현재 기준은 이전 0.4.54의 비밀번호 봇방 검증 이력이 있는 설치본의 스냅샷이며 새 버전의 전체 실기 검증 완료를 의미하지 않습니다.

**한계:** 해시가 같은 클라이언트에서 서버 규칙만 바뀌는 경우, 카탈로그 변경 없이 개별 번들이 바뀌는 경우, 실행 후 검사 간격 안에서 발생하는 변경, 이미 로더/게임 초기화 단계에서 일어난 네이티브 충돌은 전부 막을 수 없습니다. 모든 번들을 매번 해시하거나 서버 동작을 가로채지 않습니다. 구조 검사는 계산 의미의 정확성을 증명하지 않으며 새 전투 규칙은 별도 검증해야 합니다. 이 기능은 업데이트 자동 적응이나 무충돌 보장이 아닙니다.

### 0.4.55 비활성 창 음소거

모드 설정 왼쪽 진단 로그 아래에 `비활성 창 음소거` 옵션을 추가했습니다. 기본 OFF이며, ON일 때 게임 창의 포커스를 잃으면 Wwise 출력을 중지하고 복귀하거나 옵션을 끄면 복원합니다. 저장된 볼륨 설정은 변경하지 않으며 전투 기능 토글과 독립적으로 동작합니다.

빌드와 실제 제어 코드를 사용하는 자동 검사(기본 OFF, 포커스 왕복, 옵션 해제, 초기화 대기, 실패 재시도, 엔진 재시작)를 통과했습니다. 설치 후 0.4.55 로드 로그까지 확인했습니다. 사용자가 직접 확인하기로 하여 설정창 배치와 실제 음소거/복원 동작의 인게임 검증은 진행하지 않았습니다.

### 0.4.54 필드 표시 소실 진단·포커스 전환 수정

0.4.53 진단 빌드로 비밀번호 방에서 봇 3명과 테스트했습니다. 공개 버프가 없는 파루난 이름/HP와 전투 종료 후 이름표 재생성은 확인했습니다. 2026-09-20 19:31:35에 다른 창으로 포커스를 옮기자 `field clear: unfocused; count=4`가 기록되어, 포커스 해제만으로 모드 이름표를 삭제하는 경로를 재현했습니다. 0.4.54는 표시 갱신을 유지하고 포커스가 없을 때 클릭 입력/눌림 상태만 차단합니다. 최초 원본 배치·공개 효과 렌더링·사망/은신/전투/설정 OFF 숨김은 유지합니다. 이 경로가 이전 보고의 유일한 원인인지는 확정하지 않았습니다.

진단 ON일 때 숨김 사유와 슬롯별 표시/부모 연결/원본 소유자/캐릭터 숨김 상태를 변화 시에만 기록합니다. 이름·계정 ID는 기록하지 않고, 진단 실패는 표시 갱신과 분리합니다. 원본 버프 렌더링 IL 비교와 포커스 회귀 검사를 통과했습니다.

0.4.54 재실행 후에도 같은 비밀번호 방/봇 구성으로 검증했습니다. 19:37:01.887~19:37:23.776의 약 22초 포커스 해제 구간에서 이름표 삭제·재생성·예외가 없었고, 복귀 후 필드 이름/HP 표시를 화면에서 확인했습니다. 공개 매칭/다른 사용자 방에는 입장하지 않았습니다. 장시간 플레이 및 모든 캐릭터 상태를 검증한 것은 아닙니다.

### 0.4.52 필드 인디케이터 최초 방식 복원

최초 필드 기능이 포함된 보관 백업(0.4.29)과 비교해 업데이트·정리·버프 렌더링을 복원했습니다. 해당 세 메서드의 빌드된 IL이 초기 백업과 완전히 일치하는지 검사합니다. 추가 위치/렌더 순서/폰트 보정을 사용하지 않으며, 예외적으로 플레이어 표시명 `GetNick(false)`과 아군 하늘색만 유지합니다. 칩 핑 등 다른 기능은 변경하지 않습니다.

추가 요청에 따라 공개 효과(버프·속성 효과)가 0개여도 이름·HP 인디케이터를 유지합니다. 버프 목록은 생성 시 비워 원본 템플릿 아이콘이 남지 않도록 합니다. 사망·은신·화면 밖·전투 중 숨김과 설정 OFF 조건은 유지합니다. 실제 게임 화면 확인은 별도입니다.

### 0.4.51 필드 진입 크래시 긴급 복구

0.4.50 실행에서 2026-09-20 18:52:46 필드 이름표 2개 생성 직후 delegate 변환/등록 로그가 마지막으로 남았고, 18:52:47 Windows Application Error에 `GameAssembly.dll`, `0xc0000005`, 오프셋 `0x3e2cd0`이 기록되었습니다. 네이티브 덤프 분석으로 원인을 확정한 것은 아니지만, 새 IL2CPP 콜백 연결 경로가 유력하여 해당 경로 전체를 제거했습니다.

`DelegateSupport` 변환, Stage 렌더 이벤트 구독/해제, 스프라이트 경계 읽기와 머리 위 위치 보정을 제거하고 기존 원본 이름표 배치로 복구했습니다. **머리 위 이동은 이번 복구에서 보류**합니다. 플레이어 닉네임·하늘색·칩 핑 `name` 필드 수정·게임 시작 버튼 롤백은 유지합니다. 빌드/정적 검사와 실제 게임 진입 검증은 구분합니다.

캐릭터 메뉴 왼쪽의 기존 슬롯을 유지하되, 메인메뉴의 자식으로 두고 캐릭터 버튼의 실제 좌표·알파·표시·입력 상태를 매 프레임 따라갑니다. 따라서 원본 Cut in의 오른쪽→왼쪽 이동 곡선을 재사용하며 화면 숨김/재등장에도 함께 움직입니다. 1.2초 등장 대기와 고정 좌표 복원을 제거했고, 이동은 바깥 컨테이너만 변경하여 모드 버튼 자체의 호버/중앙 눌림과 충돌하지 않게 했습니다. 빌드·원본 패키지/호출 연결·좌표 검사 완료, 실제 게임 전환 확인은 별도입니다.

### 0.4.32 방어·회피 항상 한쪽 추천

방어·회피의 보류/동률 표시를 제거하고 본인·관전 모두 추천 배지와 화살표가 한쪽을 가리키도록 변경했습니다. 모든 공개 수치 조합에서 일관된 선택을 우선하고, 조합에 따라 선택이 갈리면 최악의 전투불능 확률, 최악의 평균 체력 손실 순으로 비교합니다. 완전 동률과 회피 불가는 방어입니다. 이는 보수적인 선택 정책이며 실제 결과 보장이 아닙니다. 공개 피해·확률 범위, 비정상 입력/PvP 차단, 공격·놓아주기 및 카드 계산은 유지하고 게임 버튼을 자동으로 누르지 않습니다.

### 0.4.31 조우 반격 연출·아군 필드 색상

전투 여부 선택 화면의 공식 반격 아이콘에도 기존 전투 반격과 같은 MaxPoint 확대·흔들림·잔상·효과음을 한 번 재생합니다. 원본 아이콘의 자식으로 모드 전용 효과를 겹쳐 위치·배율·표시 여부를 상속하고, 단계/대상 변경·설정 OFF 때 정리합니다. 기존 `전투 정보 표시` 토글을 따르며 전투 추천 ON/OFF와 독립적입니다. PvE 몬스터의 공개 반격 조건만 사용합니다.

PvE 플레이어 필드 이름표의 이름·체력·연결선·끝점을 하늘색으로 구분합니다. 버프 아이콘 고유 색상과 원본 몬스터 이름표는 유지합니다. 빌드·정적 연결 검사를 수행하며 실제 화면·효과음 확인은 별도입니다.

### 0.4.30 시작 공지 자동 표시 끄기

모드 실행 시 로그인 과정의 `UGUIController.IsNeedOpenNoticeWindow`만 false로 반환하여 NOTICE 자동 팝업을 생략합니다. 로그인 NOTICE 버튼과 홈 공지 메뉴의 직접 열기 경로는 유지합니다. 공지 창 자체나 게임 파일·네트워크·저장 설정은 변경하지 않으며 바닐라 실행에는 적용되지 않습니다. 빌드와 원본 호출 경로 정적 검사를 수행하며 실제 재실행 확인은 별도입니다.

### 0.4.29 칩 핑 팝업

기존 카드 핑과 같은 클릭 경로에 칩 핑을 추가했습니다. 게임의 `BattleRelicMessage.GetRelicMsg` 문구와 완전히 일치하는 핑만 인식하고, 원본 `Relic/Relic_Button_Item`의 아이콘·등급 테두리·이름·설명·cutIn 등장 전환을 모드 전용 복제본에서 사용합니다. 선택/추천/핑 전송 콜백은 연결하지 않습니다. 설명이 길면 높이를 늘리고 화면 안에 맞춰 배율을 조절합니다. 클릭·외부 클릭·Escape 닫기는 카드 팝업과 공유하며 일반 카드/칩 호버는 변경하지 않습니다.

설정 이름은 `카드·칩 핑 팝업`으로 확장하되 기존 저장 키와 ON/OFF를 보존합니다. 같은 숫자 ID의 카드/칩은 구분하며 동일 문구가 여러 항목에 대응하면 표시하지 않습니다. 소유 정보나 서버 요청 없이 공개 설정 테이블만 사용합니다. 빌드·문구/배치 자체 검사·원본 메타데이터 연결을 검사하며 실제 화면 확인은 별도입니다.

### 0.4.28 필드 플레이어 버프 표시

`필드 버프 표시` 독립 토글(기본 ON)을 추가했습니다. PvE 필드의 플레이어에게 공개 효과가 있을 때 원본 몬스터 `Common_Internal/Com_AttrInfo` 이름표·체력·버프 아이콘을 표시하며, 몬스터 일련번호는 생략합니다. 원본 필드 UI의 캐릭터/카메라 추적·겹침 완화·연결선·사망/은신/화면 밖 숨김을 재사용합니다. 클릭하면 몬스터와 같은 공개 효과 설명을 엽니다. 전투 중에는 필드 표시를 제거하고 기존 전투 표시 설정을 따릅니다.

공개 `GetShowBuffs(player, false)`만 0.2초 간격으로 읽고, 아이콘·수치는 변경될 때만 갱신합니다. 원본 `ShowAttrInfo`의 속성 이벤트 구독 대신 모드 전용 객체에서 `RefreshProperty(data, false)`를 사용하여 반복 생성/제거 시 콜백이 누적되지 않도록 했습니다. 버프 소멸·플레이어 교체·화면 교체·옵션 OFF 때 정리하며 서버 요청이나 원본 캐릭터 UI 필드는 변경하지 않습니다. 설정창은 안내 영역을 줄여 새 토글을 기존 창 안에 배치합니다. 실제 게임의 표시/클릭/겹침 확인은 별도입니다.

### 0.4.27 관전 반격 표시 지연 수정

반격 표시를 로컬 FightWindow의 선택 단계·공개 상태 행 생성·0.2초 스캔에서 분리했습니다. 본인 전투와 관전 모두 전투 연출의 방어자 공개 데이터를 읽어 아이콘을 미리 준비하고, 매 프레임 원본 DEFENSE의 표시 여부·알파에 맞춰 등장/숨김 처리합니다. 공개 상태 행이 재생성되어도 반격 연출은 다시 시작하지 않습니다. 기존 PvE/몬스터 공개 반격 조건, 옵션 OFF·대상 교체 정리와 원본 MaxPoint 연출을 유지합니다. 실제 게임에서 양쪽 시점의 등장 타이밍 검증은 별도입니다.

### 0.4.26 관전 호버 겹침 수정

방어·회피 아이콘에 붙은 설명창의 위치를 고정 오프셋 대신 아이콘의 패널 내부 위치·실제 설명창 높이·배율로 계산합니다. 등장 시 아래로 이동하는 8px도 반영해 추천 패널 위 최소 12px 여백을 확보합니다. 양쪽 아이콘과 전체 등장 구간을 검사하며 계산·문구·설정은 변경하지 않습니다. 실제 게임 화면 검증은 별도입니다.

### 0.4.25 반격 아이콘 종속·원본 등장 연출

반격 아이콘을 DEFENSE 이미지(n24) 우상단 모서리에 겹쳐 배치합니다. 해당 이미지는 자식을 가질 수 없는 GImage이므로 같은 부모 아래 모드 객체를 두되, 매 프레임 이미지의 위치·배율·표시 여부·알파를 따라갑니다. 제목이 숨겨지면 모드 아이콘과 진행 중인 연출도 즉시 숨김/중단하며, 대상 변경·전투 종료·옵션 OFF 때 정리합니다.

새로 표시될 때 설치된 `Fight/Fight_Com_Point`의 `MaxPoint` 전환을 모드 전용 복제본에서 한 번 재생합니다. 주사위 6의 1.9배 확대·흔들림, 2.2배 잔상과 페이드, 내장 효과음(510)을 재사용하고 숫자 대신 원본 반격 아이콘을 대상으로 연결합니다. 반복 점멸이나 매 갱신 효과음은 없습니다. 실제 주사위 객체·게임 결과·원본 전환 데이터는 변경하지 않으며 별도 비동기 3D 파티클(효과 52)은 생성하지 않습니다.

좌표/배율 자체 검사, 런타임 메타데이터 및 원본 전환 확인, 빌드 검사를 수행합니다. 실제 전투의 가림·효과음 크기·등장 연출은 재실행 후 확인이 필요합니다.

### 0.4.24 UI 부가 문구 제거

카드 확률·관전 방어/회피·조우 요약·설정 안내에서 ‘추정’ 문구를 모두 제거했습니다. 앞으로도 UI에 추가하지 않도록 작업 원칙과 빌드 검사를 반영했습니다. 계산식·확률 범위·조건부/판단 보류 정책은 그대로이며, 계산 가정과 한계는 이 문서에서 유지합니다. 이전 버전 설명의 UI 문구보다 이 변경이 우선합니다.

### 0.4.23 방어자 이득 비교 명확화

공격 카드 호버에서 증가폭(%p) 줄과 해당 문자열 생성을 제거하고 사용 후 상대 전투불능 확률 한 줄만 표시합니다. 내부 카드 이득 계산은 유지합니다.

본인/타인의 PvE 전투 모두 공개된 공격 눈과 능력치를 받아 방어자의 방어·회피 전투불능 확률을 비교하고, 같으면 예상 체력 손실이 적은 쪽을 추천합니다. 실제 행동을 예측하거나 이미 선택한 행동을 읽는 기능이 아닙니다. 관전 표제는 `방어자 기준 · 방어/회피 유리 · 추정`으로 명확히 하며, 각 아이콘 호버에는 기존 추천 배지를 재사용해 해당 선택의 피해·전투불능 수치를 표시합니다. 계산 조건에 따라 우위가 바뀌면 보류, 완전히 같은 값이면 동률로 표시하고 따봉을 붙이지 않습니다. 회피 불가일 때는 별도로 표시합니다. 플레이어/몬스터 구분으로 비교 방향을 바꾸지 않습니다.

계산/문자열 자동 검사를 추가했으며 실제 관전 아이콘 호버 렌더링은 별도 확인이 필요합니다. 아래 0.4.22의 증가폭 UI 설명보다 이 변경이 우선합니다.

### 0.4.22 모드 계산 기준 통일·카드 증가폭

방어·회피, 공격/방어 카드, 조우 추천이 모두 현재 HP까지의 실제 체력 손실로 비교합니다. 전투불능 확률을 먼저 비교하고 동률이면 체력 손실을 비교하는 정책은 유지합니다. 기존 방어 선택 계산만 초과 피해를 포함하던 불일치를 제거했고, 주사위 전 계산의 무피해 확률도 반환합니다. 카드 계산의 중복 방어 주사위 열거와 조우의 반복 계산을 줄였습니다.

공격 카드 호버는 사용 후 상대 전투불능 확률과 **동일한 기존 능력치·회피 조건에서 카드 한 장을 추가한 증가폭(%p)** 두 줄만 표시합니다. 예를 들어 20%에서 30%는 +10%p입니다. 서로 다른 조건의 사용 전/후 끝값을 빼서 불확실성을 부풀리지 않습니다. 방어 카드에는 추가 설명창이 없습니다. 확률 범위는 바깥쪽으로 반올림하며 극히 작은 위험/거의 확실한 결과를 0%/100%로 단정하지 않습니다.

이는 범위를 임의로 줄이거나 통계적 신뢰구간을 만든 변경이 아닙니다. 기본 공정 6면체는 가능한 눈을 모두 계산하지만, 카드 보정별 확률과 이후 회피 가능 여부가 공개되지 않은 경우 그 불확실성은 남습니다. 확률은 기본 규칙 및 기존의 방어자 선택 모델에 따른 추정이며 특수 효과·실제 AI 정책까지 보장하지 않습니다. 미공개 주사위 결과·RNG·타인의 손패를 읽지 않고 게임의 계산/행동은 바꾸지 않습니다. 외부 프로젝트 코드는 복사하거나 이식하지 않았습니다.

독립적인 36결과 열거 및 카드 조건별 대응 비교를 자체 검사에 추가했습니다. 실제 전투 화면/특수 규칙과의 검증은 별도입니다.

### 0.4.21 버튼 눌림 중앙 정렬

모드의 원본 UI 생성 코드가 축소형 버튼의 중앙 피벗을 좌상단으로 덮어쓰던 원인을 수정했습니다. 모드 설정 진입·돌아가기·크기/불투명도 ±·버프 아이콘은 중앙 기준으로 눌립니다. 배치는 평상시 배율로 피벗 좌표를 계산해 기존 위치/크기를 유지하며 누르는 동안 기준점이 이동하지 않습니다. 비대화형 안내 화살표도 새 피벗에 맞춰 기존 위치를 유지합니다. ON/OFF 토글은 기존 고정 크기·눌림 색 변화 정책을 유지합니다. 기존 게임 버튼·공용 에셋은 수정하지 않습니다. 빌드/회귀 검사와 실제 화면 검증은 구분합니다.

### 0.4.20 반격 표시·공격/놓아주기 추천

기존 `전투 공개 상태` 옵션의 화면 이름을 `전투 정보 표시`로 변경했습니다. 키와 기존 ON/OFF 값은 보존합니다. 공식 조우/몬스터 정보 화면이 공개하는 `Property.Counter.Value`가 참인 몬스터에게 `Common/Com_Icon_Counter` 원본 아이콘을 DEFENSE 표시 우상단에 붙입니다. 새 아이콘은 원본 DEFENSE 컴포넌트의 움직임을 따라가며 단계 종료·설정 OFF·대상 교체 때 제거/숨김 처리합니다. 능력을 나타내는 표시이며 실제 반격 발동을 보장하지는 않습니다. 공개 경로를 확인하지 못한 플레이어 전용 상태는 표시하지 않습니다.

`전투 추천`을 켜면 PvE 몬스터 조우의 본인 공격/놓아주기 선택에도 기존 칩 추천 따봉과 등장 모션을 재사용합니다. 기본 표시는 따봉 하나이며 `호버 수치`를 켜고 버튼에 호버하면 두 줄 요약만 표시합니다. 관전자·플레이어 상대·강제 전투·숨김/비활성 버튼·PvP·알 수 없는 맵에는 표시하지 않습니다. 데이터 확인은 기존 0.2초 주기를 사용하며 입력이 같으면 계산 결과를 재사용합니다.

계산은 공정한 6면체·최소 방어 피해 1·현재 공개 HP/공격/방어로 한 차례의 공격과 생존한 상대의 반격만 평가합니다. 회피 불가/가능(전투불능 확률 우선, 동률이면 피해 최소 선택) 시나리오를 각각 계산합니다. 상대 전투불능 확률이 자신의 반격 전투불능 위험보다 높으면 공격, 낮으면 놓아주기를 추천하며, 동률이면 현재 HP로 제한한 양쪽 예상 체력 손실을 비교합니다. 시나리오마다 추천이 다르거나 완전 동률이면 따봉을 보류합니다. 이는 기본 수치의 교환 우위 휴리스틱이지, 놓아주기의 0피해와 임무 보상을 통합한 최적 전략 계산이 아닙니다. 특수 스킬·버프 규칙·추가 카드·보상/임무/장기 자원 가치와 실제 몬스터 AI의 선택은 모델링하지 않습니다. 숨은 카드·RNG·서버 추가 요청은 사용하지 않습니다.

자동 검사와 빌드는 가능하지만 실제 게임의 아이콘 배치·따봉·호버·전투 전환 검증은 재실행 후 별도로 필요합니다.

### 0.4.14 설정창 고정 토글·호버 기능 안내

설정의 6개 토글은 원본 노란 버튼을 재사용하고, OFF에서는 배경 이미지만 회색으로 바꿉니다. 버튼 자체는 비활성화하지 않아 OFF에서도 클릭/호버가 가능합니다. ON/OFF 문구(캐릭터 이름은 본명/이명)를 함께 표시합니다. 오른쪽은 480×60, 왼쪽은 340×60으로 고정하며 선택 상태의 축소 효과 대신 원본 눌림 색 피드백을 사용합니다. 다른 게임 버튼/전역 애니메이션은 변경하지 않습니다.

왼쪽 전투 미리보기와 계산/갱신 경로를 제거하고 기능 안내로 교체했습니다. 토글 6개, 크기·불투명도 ±, 돌아가기 버튼에 호버하면 해당 항목의 짧은 설명이 바로 바뀌며 본문에 0.14초 페이드가 적용됩니다. 벗어나면 기본 안내로 돌아갑니다. 설명은 항목 변경 때만 갱신합니다. 설정 키/기존 값/Steam 기본 바닐라는 보존합니다.

빌드·고정 배치/모든 버튼의 설명 매핑 검사 및 원본 버튼 메타데이터 검사를 수행합니다. 실제 인게임 색상·상태 전환·호버 렌더링은 재실행 후 확인이 필요합니다.

### 0.4.13 전투 보조 설명 축소

공격 카드 호버를 작은 반투명 검정 패널의 원본 공격 아이콘 + `상대 전투불능 · 추정` + `사용 전 확률 → 사용 후 확률` 한 줄 비교로 바꿨습니다. 무작위 보정의 확률 범위는 유지하며 처치를 확정 예측하지 않습니다. 평균 체력 손실·추가 피해/비용·다음 턴 가치·계산 가정의 장문은 UI에서 제거했습니다. 지원하지 않는 카드에는 추가 설명창을 만들지 않습니다.

방어 카드 호버 설명과 방어·회피 버튼 위에 추가로 뜨던 계산 가정 창은 생성/갱신 코드 및 불필요한 문자열과 함께 제거했습니다. 카드 위 짧은 판단 표식, 따봉/화살표, 버튼의 짧은 피해·전투불능 수치, 공개 버프 설명은 유지합니다. 설정 명칭은 `호버 수치`이며 기존 설정 키와 값은 보존합니다. 이런 최소 정보 원칙은 AGENTS.md에도 반영했습니다.

추정은 기존 기본 6면체/최소 방어 피해 1/전투불능 우선 비교 규칙이며, 카드 확률은 공개 보정 범위와 이후 방어·회피 가능/불가 시나리오의 범위입니다. 특수 효과·추가 카드·장기 자원 가치는 계산하지 않습니다. 상세 가정은 문서에만 두고 반복 UI 문구로 출력하지 않습니다. 빌드/회귀 및 기존 수치 일치 검사를 수행하며 실제 화면 크기·호버 확인은 재실행 후 필요합니다.

### 0.4.12 전체 UI 갱신·계산 최적화

버프/손패 줄뿐 아니라 이름 치환, 전투·카드 계산, 핑 팝업, 설정창, 추천 모션과 공통 런타임 연결을 점검했습니다. 이름 치환 탐색을 프레임당 최대 64회 작업·약 1ms의 분할 작업으로 바꾸고, 버프는 ID·중첩·남은 턀이 바뀔 때만 원본 렌더러를 호출합니다. HP 위치 추적은 매 프레임 유지하며 데이터 갱신은 기존 0.2초입니다. 공통 UI 포인터 경로는 프레임당 한 번 조회하고, 메타데이터/동일 입력 계산은 재사용하며 정지한 팝업·설정창·따봉의 중복 속성 쓰기와 계산 내부의 미사용 문자열 생성을 줄였습니다. 게임의 원본 애니메이션·시간 배율·FPS 설정은 변경하지 않습니다.

기존 DLL과 342개 계산 결과/한국어 설명을 비교했고 일치했습니다. 오프라인 계산의 관리 메모리 할당은 넓은 전투 범위 173,345→737 bytes/호출, 넓은 카드 범위 897,089→190,089 bytes/호출입니다. 이는 실게임 FPS 측정이 아닙니다. 실제 프레임 지연 감소·UI 전환·호버·페이지 변경 확인은 재실행 후 필요합니다.

기존 `충돌 진단 로그`를 ON으로 하면 10초 단위 `performance` 요약에 모드 UI 평균/최대 소요 시간, 기능별 최대 시간, 관리 메모리 할당, 게임 프레임 간격을 기록합니다. 기본 OFF와 용량 제한은 유지합니다. 자세한 범위·측정법·한계는 [전체 점검 기록](performance-audit-0.4.12.md)을 참고하세요.

### 0.4.11 HP 아래 한 줄 전투 상태

캐릭터 그림 전체의 크기에 영향을 받던 머리 위 배치를 제거했습니다. 공식 공격자/방어자 `txt_Life`의 아래쪽 가장자리를 실제 전투 카메라로 투영하여, 공격자는 왼쪽·방어자는 오른쪽 바깥 방향으로 펼칩니다. 위치는 매 프레임 HP 표시를 따라가며, 가장자리에서는 바깥 공간에 맞게 축소하고 HP가 숨겨졌거나 아래 공간이 없으면 함께 숨깁니다. 손패 아이콘/장수·버프·페이지를 높이 52의 한 줄로 압축하고 손패 문구는 호버로 옮겼습니다. 72% 불투명 검정 배경·효과 호버 설명·휠 페이지·독립 토글은 유지합니다.

빌드·HP 정렬/추적/영역 경계 자체 검사·설치된 게임의 필드와 좌표 변환 메서드 검사를 수행합니다. 실제 전투의 겹침·스킨별 위치 확인은 재실행 후 필요합니다.

### 0.4.10 머리 위 전투 상태·반투명 배경·캐릭터 추적

손패 장수/공개 효과 줄을 캐릭터 머리 위로 이동하고 72% 불투명 검정 배경을 복원했습니다. 배경 폭은 현재 표시하는 아이콘 수에 맞춥니다. 기존 관리 객체의 피벗 대신 게임의 Animator/SpriteShake 대상인 `BattleActor.actorRenderer`의 `SpriteRenderer.bounds` 상단을 전투 카메라로 매 프레임 투영하여 캐릭터 그림의 이동·스케일·프레임 크기 변화를 따라갑니다. 데이터 갱신은 기존 0.2초 주기를 유지하고 위치 갱신과 분리합니다. 그림이 없거나 비활성/화면 밖이면 숨기며, 머리 위치는 그림 상단 기준이라 무기·모자가 큰 스킨에서는 여백이 달라질 수 있습니다.

기존 호버 설명·휠 페이지·독립 ON/OFF·공개 정보 제한은 유지합니다. 위치 계산 자체 검사와 설치 게임 메타데이터 검사를 수행하며 실제 전투의 READY/능력치와 간격 및 애니메이션 추적은 재실행 후 확인이 필요합니다.

### 0.4.9 충돌 진단 로그 토글

모드 설정 왼쪽 아래의 `충돌 진단 로그`는 기본 OFF이며 전투 추천 토글과 독립적으로 즉시 적용·자동 저장됩니다. ON으로 저장하면 다음 모드 실행의 초기화부터 기록합니다. 일반 BepInEx 오류 로그와 Steam 바닐라 실행 설정은 변경하지 않습니다.

ON일 때 모드 버전·관리 런타임 버전·실행 파일명·설정 값, 메뉴/전투 단계 변화, UI 생성 시작/완료, 모드가 처리한 예외의 종류와 호출 경로만 로컬 기록합니다. 계정·채팅·손패 내용, 전체 실행 인자·개인 경로·예외 메시지는 추가 진단 파일에 기록하지 않습니다. 매 프레임 출력이나 전역 Unity 로그 후킹은 하지 않습니다.

위치: `8vJXnINT/BepInEx/BetterAstralParty-Diagnostics/current.log`, 직전 활성화 기록은 `previous.log`. 각 파일 최대 1 MiB, 총 2개를 유지하며 한도/쓰기 오류 시 진단 기록만 중단합니다. OFF → ON으로 다시 시작할 수 있습니다. OFF는 기존 기록을 삭제하지 않습니다. FlowSDK의 네이티브 충돌을 복구하는 기능이 아니며 Windows 덤프와 함께 분석해야 합니다. 빌드·진단 자체 검사를 수행하며 실제 인게임 토글 렌더링은 별도 확인이 필요합니다.

### 0.4.8 전투 상태 위치 수정

### 0.4.7 전투 공개 상태

PvE 전투의 양쪽 캐릭터 발밑에 공개 손패 **장수**와 공식 버프·디버프 아이콘을 표시합니다. 공식 `GetShowBuffs(player, false)` 필터와 `Button_Buff`의 중첩/진행·남은 턴 표기를 재사용하며, 값이 없는 지속시간은 표시하지 않습니다. 손패 내용·쿨타임 조회·추가 서버 요청은 사용하지 않습니다.

효과 설명은 클릭 없이 호버로 열립니다. 설치된 한국어 번역과 공식 설명 부품을 사용하고, 효과가 6개를 넘으면 해당 줄에서 휠로 페이지를 넘깁니다. 설정의 `전투 공개 상태` ON/OFF는 전투 추천과 독립적입니다. 필드·기존 버튼·게임 폰트·기본 바닐라 실행은 변경하지 않습니다.

필드 공식 구현은 추출한 INT 런타임의 `BattleInfoPanel.RefreshBuff`, `UICom_AttrInfo.RefreshBuff/OpenBuffInfo`, 플레이어 이름표 클릭의 `BattlePlayerInfoWindow`에서 확인했습니다. 빌드·자체 검사·런타임 메타데이터 연결 검사를 수행하며 실제 PvE 렌더링/호버/배치는 재실행 후 확인해야 합니다.

### 0.4.5 일반 카드 호버 팝업 제거

0.4.3에서 추가했던 일반 카드 이미지 호버 확대를 제거했습니다. 원래 게임의 손패 호버·확대와 기존 전투 추천 설명은 그대로 유지합니다. 카드 핑 말풍선 클릭으로 여는 팝업, 등장·퇴장 애니메이션과 ON/OFF는 유지하며 설정 버튼은 `카드 핑 팝업`으로 명확히 표시합니다. 기존 설정 값을 보존하기 위해 config 키 `카드 확대 팝업`은 유지합니다. 아래 0.4.3~0.4.4의 일반 카드 호버 확대 설명은 더 이상 적용되지 않습니다.

### 0.4.4 카드 팝업 전용 토글

모드 설정에 `카드 확대 팝업 ON/OFF`를 추가했습니다(기본 ON, 자동 저장). 전투 추천·호버 설명 설정과 독립적으로 카드 핑 클릭 및 카드 이미지 호버 팝업을 함께 켜고 끕니다. OFF에서는 열린 팝업과 추가된 핑 클릭 영역을 제거합니다.

원본 설정 버튼을 재사용하고 우측 토글을 3행으로 배치했습니다. 창 크기·하단 돌아가기 버튼을 유지하며 항목이 창 안에 들어가므로 스크롤은 추가하지 않았습니다. 원본/대체 버튼의 배율·행 간격과 해상도별 창 경계 자동 검사는 통과했습니다. 실제 화면의 배치와 토글 조작 확인은 재실행 후 필요합니다.

### 0.4.3 카드 확대 팝업

PvE에서 공개된 카드 핑 말풍선을 클릭하면 원본 `Common/Com_Card` 앞면을 고정 팝업으로 표시합니다. 화면에 보이는 앞면 카드 이미지에 0.25초간 호버하면 같은 팝업을 잠시 표시하고, 벗어나거나 카드 클릭·드래그를 시작하면 닫습니다. 고정 팝업은 닫기 버튼/팝업 클릭, 같은 카드 핑 재클릭, 외부 클릭 또는 Esc로 닫습니다. 게임 입력을 가로채지 않으므로 외부 클릭과 Esc의 기존 게임 동작도 유지됩니다.

원본 카드 렌더러·번역·비용/종류 아이콘을 사용하며 기본 카드 일러스트로 표시합니다. 원본 설명 펼침 전환이 있으면 재생하고, 새 팝업에만 0.18초 등장·0.12초 퇴장 페이드/슬라이드를 적용합니다. 기존 카드의 배율·애니메이션과 정적인 추천 표식은 변경하지 않습니다. 호버 팝업은 입력을 받지 않아 원래 카드 사용·드래그를 막지 않습니다.

핑은 게임의 `BattleCardMessage.GetCardMsg`가 만든 문구와 완전히 일치할 때만 대응합니다. 중복 이름/문구, 뒷면, PvP/미확인 모드는 표시하지 않으며 다른 사람의 손패·네트워크에는 접근하지 않습니다. 0.4.4부터는 전용 토글로 팝업을 켜고 끕니다. 빌드·배치·완전 일치/중복 차단 자동 검사는 통과했으며 실제 PvE에서 클릭/호버와 애니메이션 확인은 필요합니다. 로그 접두사는 `[카드 확대]`입니다.

## 실행 모드

- 현재 설치 설정에서 BepInEx `[Logging.Console] Enabled=false`로 별도 로그 콘솔 자동 표시를 끕니다. 모드 시작 후 콘솔이 포커스를 가져가는 원인을 제거하며 `[Logging.Disk] Enabled=true`로 파일 로그는 유지합니다. 게임 창을 반복해서 강제 활성화하지 않으므로 사용자가 다른 앱으로 전환한 경우 포커스를 다시 빼앗지 않습니다. 실제 실행 포커스 확인은 다음 실행 때 필요합니다.
- Steam에서 INT(Global) 실행 또는 `AstralParty-Vanilla.cmd`: BepInEx와 BetterAstralParty를 로드하지 않습니다. 한국어 패치는 유지됩니다.
- 설치는 `Install.cmd`를 실행합니다. Steam 라이브러리에서 INT 설치 경로를 찾고, Steam 정상 종료·재시작에 동의하면 현재 로그인한 계정에 비 Steam 항목 `Astral Party - Mod`를 등록합니다. 여러 설치가 감지되면 추측하지 않고 `tools/install.ps1 -GameRoot <INT 폴더>` 지정을 요구합니다. 게임이 실행 중이면 설치를 차단합니다.
- 모드는 Steam 라이브러리의 `Astral Party - Mod` 또는 기존 `BetterAstralParty-Mod.cmd`로 실행합니다. CMD도 같은 비 Steam 항목을 호출합니다. 숨김 PowerShell 실행기가 호환성 검사를 통과한 뒤 INT EXE에만 일회성 모드 인자를 전달합니다. CN을 선택했던 `-applaunch 2622000`은 더 이상 사용하지 않습니다.
- 실행기는 `doorstop_config.ini`를 변경하지 않습니다. 설치 기본값은 `enabled=false`이며, 모드로 플레이한 다음 Steam에서 실행해도 바닐라입니다.
- 모드/바닐라 전환 전 게임을 종료하세요. 이미 게임이 켜졌으면 실행기가 중복 실행을 차단합니다.
- 원본 게임의 Steam 실행 옵션·시스템 환경 변수·게임 인증 코드는 변경하지 않습니다. 모드 자식 프로세스에만 `SteamAppId=2622000`을 전달해 게임이 원래 소유한 App ID로 Steamworks를 초기화하도록 하며, 오버레이용 `SteamGameId`는 Steam이 지정한 비 Steam 항목 ID를 유지합니다.
- Steam 등록기는 기존 바로가기를 보존하고 동일 경로의 재설치 시 중복 등록하지 않습니다. 기존 `shortcuts.vdf`를 수정할 때는 `.BetterAstralParty-날짜.bak`을 남기고 원자적으로 교체합니다. 알 수 없는 바이너리 형식·중복 키·실행 중인 Steam은 쓰기를 차단합니다. 별도 PowerShell 7 설치는 필요하지 않습니다.
- `tools/set-loader-mode.ps1 -Mode Vanilla`는 바닐라 기본값 복구용입니다. 예전 `-Mode Mod` 전역 활성화는 차단했습니다.

Steam 원본 항목에서는 INT(Global)를 선택하세요. 모드 전용 항목은 INT로 고정되며 실행 항목 번호를 추측하지 않습니다. Steam 오버레이는 전체 설정과 바로가기 설정에서 활성화되어 있어야 합니다. 비 Steam 항목은 계정별 로컬 등록이며, 설치 폴더를 옮기거나 다른 Steam 계정에서 사용하려면 재등록해야 합니다. 스크린샷은 원본 게임이 아니라 모드 전용 항목 아래 저장됩니다.

실행기 검증: `tools/test-launchers.ps1`은 기본 OFF·실행별 옵션·설치본 일치·전역 활성화 차단 및 바이너리 바로가기 보존/손상 차단을 검사합니다. 2026-09-23 전용 비 Steam 항목으로 INT 프로세스, 모드 0.4.66 로드, 한국어 타이틀 화면, Steam 오버레이 화면 및 실제 스크린샷 파일 생성을 확인했습니다. 이 PC의 사용자 지정 단축키는 오버레이 `Alt + 숫자패드 -`, 스크린샷 `Shift + F12`입니다. 온라인 매칭은 실행하지 않았습니다.

변경 전 실행기·설치기·README·설정 백업은 `artifacts/launcher-backups/20260923-213224`에 있으며 `SHA256.csv`로 검증했습니다. 기존 CMD 복원은 해당 `installed` 폴더에서 같은 이름의 파일을 복사하면 되지만, 그 버전에는 Steam CN 실행 문제가 남아 있습니다. 안전한 바닐라 실행은 원본 Steam INT 항목을 사용하세요. 모드용 Steam 항목 제거는 Steam의 해당 비 Steam 바로가기 제거 기능을 사용합니다. 원본 게임 항목을 제거하지 마세요.
