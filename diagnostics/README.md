# Local diagnostics collector

DiagnosticBundle.cs and MinimalDiagnosticProjection.cs are compiled into the Windows .NET Framework launcher and the net6.0 plugin. The standalone tool needs neither PowerShell nor an SDK, download, game startup or network. Keep Create-Diagnostics.cmd, Open-Logs.cmd and artifacts/BetterAstralParty-Launcher.exe together in the extracted whole package.

Use Create-Diagnostics.cmd to create a ZIP, and Open-Logs.cmd to open the unified output folder. An optional explicit INT folder can be supplied with `Create-Diagnostics.cmd --game-root "C:\\SteamLibrary\\steamapps\\common\\Astral Party\\8vJXnINT" --language en --no-open`. No additional file patterns or arbitrary input files are accepted.

The hub is LOCALAPPDATA/BetterAstralParty/Diagnostics, with TEMP/BetterAstralParty/Diagnostics as a fallback. Output is a new timestamp/random-name ZIP containing README.txt, summary.json and logs/*.log. Fixed mod-owned installation/bootstrap/launcher/compatibility error logs retain redacted detailed text, including messages, DLL names, HRESULT, stages and stacks; general game diagnostic logs retain typed projections. ZIP names never contain original user filenames or source paths. There is no uploader. Users inspect the archive and attach it themselves. Sources are read in place and are never deleted, moved or rotated by this collector.

## Source allowlist

| Root | Exact paths or anchored name rule |
| --- | --- |
| Verified INT game root | BepInEx/BetterAstralParty-Diagnostics/current.log, previous.log, combat-mismatch.log, combat-mismatch-previous.log |
| Verified INT game root, collected first | BepInEx/BetterAstralParty-Diagnostics/minimal-v1/events-current.jsonl, events-previous.jsonl, helper/events-current.jsonl, helper/events-previous.jsonl |
| Verified INT game root | BetterAstralParty-Compatibility.log, BetterAstralParty-LaunchError.log: redacted detailed error text; BepInEx/LogOutput.log: metadata only |
| LOCALAPPDATA/BetterAstralParty/Logs; TEMP/BetterAstralParty | Launch-32_lowercase_hex.log; Bootstrap-32_lowercase_hex.log; BetterAstralParty-InstallError-yyyyMMdd-HHmmss-8_lowercase_hex.log: redacted detailed error text |
| USERPROFILE/AppData/LocalLow/feimo/AstralParty_INT | Player.log, Player-prev.log: metadata only; zero content bytes read |

The Unity root is derived from the existing check-compatibility.ps1 cache root. Real Unity log generation at this path has not been tested in this task. The game root requires AstralParty_INT.exe and AstralParty_INT_Data markers; neither is executed or included. The plugin DLL is accessed solely for a strictly numeric or alpha/beta/rc product-version resource; it is not loaded or included. pluginFileProductVersion is explicitly separate from the actual BepInPlugin constant: that constant is unknown in the standalone host, while the in-game host passes its own Plugin.Version with running-plugin provenance. Strict loggedModVersion fields can be retained from historical diagnostic headers; they do not prove the current installed version. No receipts, full configurations, private release/channel URLs, updater state, request tickets, credential stores, raw dumps, WER files or arbitrary files are collected.

Only content files modified within 7 days are eligible; timestamps over a day into the future are skipped. Engine metadata includes any present file's size/mtime, with its content unread. There are 24 log slots, 8 recent entries per dynamic directory, 512 top-level directory-entry inspections, 2 MiB per input file, 8 MiB total input, 512 KiB per projected file and 4 MiB total projected logs. The ZIP itself is capped at 4 MiB plus 256 KiB metadata/compression overhead. Oversized source files are skipped rather than tailed. Truncation happens only at complete projected line boundaries and is declared in summary.json. An all-missing archive is valid and explains missing evidence; it cannot recover events that were never logged. A file with no allowed records is metadata-only-no-allowed-records, not successful observation.

## Privacy and path rules

The logging audit found legacy local card IDs/effect structures in cardEffect, cardCounter and koMinimum.content, including latest snapshots in mismatch archives. General game diagnostic logs drop these records, hand/card/chat/hero/passive payload, unknown text, original exception stacks/messages and unfinished last lines. They reserialize only fixed lifecycle/gate enums, typed performance fields, selected settings booleans/UI numbers, standard error types and minimal public phase/input/HP comparison fields. Combat modifiers, card previews and original session IDs are excluded. Fixed installation/bootstrap/launcher/compatibility error files instead preserve their detailed error text: sensitive lines and their continuations become [redacted], private paths become [path] with code-file basenames retained, URLs and recognized account identifiers are masked. Closed error files may lack a final newline; their final line is retained. BepInEx/Unity remain metadata only, with no content reads. Counts and contentKind are recorded for every content source. Existing size, age and file-count limits still apply; this is not an unlimited dump of all historical logs.

General game logs use secret/account/token/path/URL/ID patterns and key blocks before their strict projection. Detailed error text uses redaction rather than a field-only summary, so unrecognized personal data can remain. It does not guarantee complete anonymisation; users must review the ZIP before sharing. The collector does not change original local logs. Installation failure records now also include HRESULT and the exception chain, without a transcript or environment dump.

Roots must be ordinary local drive paths; UNC/device/ADS/traversal/trailing-dot aliases and long paths are rejected. Every ancestor is pinned by a Windows directory handle without delete sharing. Each source file is opened with OPEN_REPARSE_POINT and shared read/write/delete to permit logger rotation, then checked for final path identity, type, reparse attributes and hardlink count. Metadata version resources retain a pinned file lease to prevent a path replacement before metadata lookup. Junctions/symlinks/hardlinks fail closed. Exclusive locks, truncation and decoding errors are reported per source. Size, mtime and final path are rechecked after reading. An active log is a best-effort snapshot; same-size edits with indistinguishable mtime can escape change detection. Unterminated final records are dropped. No read-lock guarantee or runtime overhead claim is made.

Only sanitized data reaches an in-memory ZIP and local output. A private random partial file is committed by handle rename without replacing existing output. Failure marks that exact owned handle for deletion. No filesystem traversal cleanup is used. Existing ZIPs and guide files are preserved. The collector reports fixed status codes and logical source IDs, not exception messages or personal paths. Directory scans and regex work are bounded. Hub write probes/failed partial cleanup affect only newly created output files, never source logs.

summary.json distinguishes observed file size from content readBytes and export bytes, redacted/dropped/projected counts, metadata-only, malformed/old/locked/capped/missing and changing snapshots. Missing means not observed, not no error. Requested recording and live writer health remain unknown. Legacy current/previous/mismatch files can belong to different sessions and are not correlated; structuredProjection describes only bundle-local JSONL aliases. Cross-file ordering remains unknown. HP agreement is limited public evidence and does not validate the full model. No recovery state is used to infer a successful install/update. Unknown structured schemas/events fail closed with fixed rejection counts.

## Error codes and folder dispatch

Legacy error occurrences are retained even when the raw exception type is unsupported. error_type and error_site use the fixed names in the frozen minimal logger contract. Known legacy labels map to its feature categories and a separate fixed legacy_feature code distinguishes ShushuShield, BattleStatus and other owned subfeatures. Unknown labels use the legacy projection's Unknown feature bucket; this is not a structured JSONL schema event. Unknown type names are never exported. ArgumentNullException maps to ArgumentException; known owned custom exceptions use the contract's error class. These are classifications, not a root-cause verdict.

The b3 correction audits 28 Compatibility.Block callsites and their constants/dynamic PatchFeature calls, registering exactly 15 case-sensitive feature keys. Compatibility.ShushuShield and Compatibility.BattleStatus retain PublicCombat with distinct fixed CompatibilityShushuShield/CompatibilityBattleStatus subfeatures. FieldBuffs, HandLayout and the other audited keys also retain their own subfeature and fixed producer feature category. Implementation type names such as ShushuShieldUi and arbitrary suffixes are not accepted as aliases. Unknown keys remain Unknown without exporting the original label. New producer keys require another explicit audit and allowlist update.

CompatibilityFixture.cs compiles the unchanged Compatibility.cs and DiagnosticLog.cs, uses the exact shield constant and battle call expression with inert cleanup/native/logger substitutes, and collects the produced synthetic log into a ZIP. C# checks validate producer-to-collector keys and privacy; they do not execute the actual shield/battle UI or native bridge.

The first recognized owned anchor among at most 16 following stack frames provides error_site. The frame text, parameters, files, paths and line numbers are discarded. Missing frames, generated async frames, native bridges and other unrecognized locations remain Unknown. Unknown events do not disappear merely because their class or feature is unsupported. Private-key continuations and incomplete final records are still excluded.

AcquireHub returns a disposable FolderLease. Its Open callback rechecks the type/reparse/path/identity and keeps ancestor directory handles pinned until synchronous dispatch returns. BundleResult.OpenFolder checks the directory identity captured during ZIP commit; same-path replacement by a regular directory or junction is rejected. Dispose leases in finally/using. GetHub remains a string convenience API and must not be used for shell dispatch. No command string is constructed. Explorer may resolve the path asynchronously after Process.Start returns, so this does not guarantee object identity for Explorer's later work. Failure to open a folder preserves the generated ZIP.

The b2 collector includes the frozen minimal JSONL producer projection and changes only its collector-side copy. It validates the exact v1 schema, field types/ranges, fixed enum names and complete lines within 2 KiB. It preserves stages, safe failure/site/codes, session/operation relations, hook registration/observation/samples, worker health/drop/rotation, settings subset and snapshots. StageSnapshot/FailureSnapshot remain distinct event kinds; cumulative error counts are not added or relabeled as new events. The observed writer state is historical, not current health. Sequence and elapsed time remain scoped to the process; separate process timestamps do not establish causality.

Session and operation GUIDs are replaced with fresh random bundle-local aliases shared across all four sources. Equal original operation/related-operation values retain equal aliases, including worker-parent links, while originals never enter the ZIP. Separate bundles have separate aliases. Maps have 64 session and 512 operation limits. This reduces identifier correlation and does not guarantee anonymisation: public build IDs, versions, times and counts remain.

Unknown event/enum, field or schema values never become raw exports. projectionRejections in each summary row reports only the fixed reason and count: unknown-enum, unknown-field, unsupported-schema, invalid-field, malformed-record, record-limit, incomplete-record or identity-limit. Dropped records may include failures; missing or rejected data is not evidence of success. Files with no valid events still have metadata/status/rejection counts. Existing read/output quotas and fences also apply to these sources. State markers, locks, tickets, receipts, dumps and other files remain excluded.

## Integration

For the initial b1 proposal, diagnostics.patch adds the collector/tool/fixture/UI bridge and main-ui-package.patch separately proposes shared integration. The b2 diagnostics-b2.patch and main-ui-b2.patch are differential corrections against that b1 work snapshot; apply b1 first and verify b2 baseline hashes. The b2 main patch moves the diagnostic cases into ApplyCore and adds the projector to the runtime and whole-package required inputs. Apply diagnostics-b3.patch after b2 for the Compatibility feature-key correction; it changes only collector/docs and dedicated fixtures, with no shared UI/Plugin/installer/packager edit. Do not also apply the producer's collector-integration/projection patches: those are already reconciled here. Main still owns producer instrumentation/lifecycle integration, feature version and signed package manifests. The eight-file install/update receipt remains unchanged: the standalone tool stays in the extracted whole package; the in-game collector is compiled into the plugin DLL. Any future installer shortcut or tool copy must be added by the installer owner with its receipt, rollback, update and uninstall rules reviewed together.

Run `Developer.cmd test diagnostics-runtime` and `Developer.cmd test diagnostics-structured` against new synthetic output roots. Additional collector/UI parity checks remain part of the required migration matrix until their C# ports pass. The fixtures supply synthetic roots and fake native/config/shell boundaries; they do not render native UI, open Explorer, discover default roots or run the game. Generated fixture files and bin/obj are local evidence, not package inputs.

Do not copy the entire work tree into the product. Check base hashes and apply only the reviewed file list. The parent owns feature version assignment and final package input manifests. Do not label this isolated implementation as shipped or reuse a pinned catalog/build identity after changing the plugin.
